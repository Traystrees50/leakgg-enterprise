## Regex / platform detection — with sources

### 1. Stake.com vs Stake.us — #stake-codes
Source: channel https://discord.com/channels/1412350608786325536/1423549369365565470, CodeStats App, Nov 24–26, 2026, all Table 1 rows; pinned example Jun 22, 2026.
Reliable signals, in order:
(a) role mention in message text @Stake.com vs @Stake.us;
(b) claim-link domain stake.com vs stake.us and its currency parameter `currency=ltc` (com) vs `currency=sweeps` (us) — present on USER SUBMITTED links, absent on some BONUS DROP links, so check the domain first;
(c) value currency $ (com) vs SC (us);
(d) requirement verb "wagered" (com) vs "played" (us).
Code prefix is NOT reliable: `stakecom...` (e.g. stakecom4gpxsae9w8c7w0, Nov 26 4:34 PM) and `stakeus...` (e.g. stakeusnh3j9gmi5bmahx, Nov 26 3:36 PM) are reliable when present, but a large minority are `stake` + random letters with no com/us segment — `stake` + pyq6... (stakepyq6arvne0ogq6m0, Nov 26 2:52 PM), `stake` + tr... (staketrhuh8824dyokyqh, Nov 26 5:50 AM; staketr8z62wib21kn3uk, Nov 24 10:02 PM), `stake` + pl... (stakepl3a3gt53hqfbbt4, Nov 26 1:09 AM), `stake` + try... / pyez... (Nov 25) — all of those are Stake.com in the observed rows, but that is INFERRED from only those examples plus their role/embed, so do NOT hard-code "stake+anything = .com"; always read the role/embed.
Bare lowercase codes with no "stake" at all (shadow8ii33, kairosaa99ii, tuvrd7p5, 7wamg2cc, 7lktqwha, hkyizm1u, izxlfh0wisk18u, wings7ii2, samurai88y11, ninja3ty5, 4bir2iuko1nj, violence2e33) carry NO platform in the code — see rule 2.

### 2. AMBIGUOUS — both-platform user-submitted codes, #stake-codes
Source: same channel, Nov 24: samurai88y11 3:45 PM, ninja3ty5 8:16 PM; Nov 25: shadow8ii33 12:35 PM, kairosaa99ii 2:11 PM, tuvrd7p5 5:49 PM, 7wamg2cc 5:51 PM, 7lktqwha 5:52 PM, hkyizm1u 8:12 PM.
These messages mention BOTH @Stake.com and @Stake.us and contain BOTH claim links (stake.com currency=ltc AND stake.us currency=sweeps), with no value or requirement. An extractor that takes the first platform mention, the first link, or the code prefix will assign them to the wrong platform half the time.
Correct handling: mark platform = AMBIGUOUS / BOTH, do not guess; if a single platform is required, the claim-link currency (ltc vs sweeps) must be kept as two separate candidate links.
Contrast with single-platform user-submitted codes in the same channel, e.g. izxlfh0wisk18u (Stake.com only, Nov 25 2:11 PM) and wings7ii2 (Stake.us only, Nov 25 4:03 PM), where the single role + single link does identify the platform.
